## v1.3 "Vivid" treatments

v1.3 rebuilt all 32 themes around a stronger hierarchy. Every root is a solid
focal block; second tiers take a per-branch fill (`secondPalette`, one shared
readable ink) and, where useful, relationship lines follow `branchPalette`.
Both are applied at render time and never written to node data. Explicit user
fills, borders and shapes still win. v1.2 specifications remain in Git history
and the [v1.2 evidence](assets/v1.2/after/contact-sheet.jpg).

## Design boundaries

The visual layer uses `defineTheme()`, hierarchy tokens and small deterministic
SVG decorations. It never writes style into node data. All original `mappop-*`
IDs remain valid. Explicit node shape/fill/border/padding overrides and retained
custom theme geometry suppress additional decoration on the affected nodes.
The upstream engine, Vue 2 framework, layouts, API and storage service are unchanged.

There is one SVG defs group and one active embedded-font style per map. Filters
are limited to title tiers; leaves never receive a shadow filter. Pattern artwork
is original local vector geometry. Hover motion is decorative only and respects
`prefers-reduced-motion`; export stays static. See [font licenses](../web/public/mappop/fonts/ART-FONTS.md).

At 121/500 nodes or 390px wide, fit-to-canvas is an overview. Zoom, pan and collapse
branches to read; theme selection never silently changes the document layout.

## Stable registry and discovery

`web/src/mappop/theme-tokens.js` is the single registry. Runtime, selector, tests
and capture scripts derive their iteration lists from it. A separate release
assertion requires at least 32 unique IDs and retains all original 16 IDs.

Families and appearance are independent: **After dark includes Pixel Arcade and Glass Aurora**.
Search matches Chinese/English names, visible descriptions and optional keywords.
Chinese UI leads with the Chinese name; every thumbnail uses the same seven-node
sample. Theme application never changes the user's selected layout.

## Ready and fallback behavior

Local fonts are prepared on demand with a 12-second deadline. SVG/PNG/PDF exports
wait for the current font and two stable layout frames, including native SMM
imports. The wait cancels if the theme changes and has a 15-second ceiling.
Direct callers can use `mindMap.waitForArtTheme({ signal, timeoutMs })`.

A failed font produces a visible fallback status. Editing and editable SMM export
remain available; image export asks for a reload instead of silently making an
incomplete-font image. A failed family is not repeatedly fetched in that session.
Only active theme fonts and decorations are embedded. User-selected external
fonts retain the upstream portability limits; local GB2312 subsets do not cover
all traditional or rare characters, which use the platform fallback.
